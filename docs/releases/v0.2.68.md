# Packet28 v0.2.68

This patch fixes three issues found while evaluating the published v0.2.67 package in isolated developer and agent workflows.

- Daemon startup now handles Unix socket paths that exceed the platform limit. It falls back to a workspace socket or authenticated loopback TCP and preserves unrelated files at the unusable path.
- Failed legacy searches now include bounded ripgrep stderr, including regex syntax errors and their locations. No-match searches keep their existing behavior.
- Uninstall now lists retained Packet28 instruction files and explains how to remove the Packet28 section while preserving user rules. It does not edit those instruction files.

The fixes include regression coverage for socket limits and live endpoints, bounded UTF-8 diagnostics, and retained guidance. Independent macOS arm64 runtime checks verified setup, index readiness, doctor, indexed search and cleanup over both fallback transports.

## Upgrade

```sh
npm install -g packet28@0.2.68
cd /path/to/workspace
packet28 daemon stop
packet28 setup
```

Restart existing agent sessions after upgrading. Updating the package does not replace an already running daemon or HTTP hook server. Stop any remaining old HTTP server using its verified PID before reinstalling hooks.
